# tea-shop: демо2 → основной сайт, редизайн главной, подстраницы сортов

Дата: 2026-07-31
Статус: согласовано с пользователем в диалоге, ожидает финального ревью спеки

## Контекст

Проект `tea-shop` (`antioz/tea-shop`) — демо-сайт чайного магазина 野馬茶 (Wild Horse Tea).
Сейчас в репозитории два демо (`demo1/` — «Редакционный», `demo2/` — «Досье экспедиции»)
и корневой `index.html` со страницей выбора между ними.

Это демо-версия сайта. Боевая версия магазина (с реальным чекаутом, реальной
интеграцией МойСклад/RetailCRM) будет собрана отдельно на Тильде — решение
пользователя, зафиксировано в этом диалоге. Задача этого спека — довести
демо2 до презентабельного состояния как самостоятельный сайт, не боевой backend.

Решено: демо2 становится основным (единственным) сайтом в репозитории.

## Из чего собран demo2 (as-is)

- Кастомный «design canvas» рантайм: `support.js` подтягивает с unpkg.com
  React/ReactDOM/Babel standalone и на лету компилирует JSX внутри `<script type="text/x-dc">`.
  `image-slot.js` — вспомогательный слой для работы с картинками в этом рантайме.
  Работает только по http(s) (не `file://`), из-за CORS на fetch к unpkg.
- Один файл `index.html`: `<x-dc>` содержит разметку с `{{ выражение }}`-интерполяцией
  и `<sc-for list="{{ array }}">` для списков.
- Текущие секции: `nav` (фикс.) → `hero` (фото + Кен-Бёрнс + параллакс) →
  `catalog` (`teas[]`, сейчас 4 шуточных плейсхолдера с нецензурными названиями —
  подлежат полной замене на реальный каталог) → `ritual` (3 принципа) → `footer`.
- `demo2/images/` — реальные фото (plantation.jpg, ritual.jpg, логотип, 4 карточки чая).

## 2. Видео-фон hero

Тег `<img>` с анимацией `kenBurns` заменяется на:

```html
<video autoplay muted loop playsinline poster="./images/plantation.jpg" style="width:100%;height:100%;object-fit:cover;filter:brightness(.45) saturate(.75) contrast(1.08);">
  <source src="./images/hero.mp4" type="video/mp4">
</video>
```

- `poster` = текущее фото plantation.jpg — запасной кадр, пока видео грузится или
  если браузер не воспроизводит автоплей (некоторые мобильные Safari без явного
  жеста пользователя).
- Оверлей-градиент и parallax-transform на обёртке (`heroImgParallax`) не меняются —
  применяются к тому же div, просто внутри него видео вместо картинки.
- `hero.mp4` — плейсхолдер: бесплатный сток-клип (туман/горы/чайная плантация),
  подбирается на этапе реализации; пользователь заменит на свой файл позже —
  для этого достаточно перезаписать `images/hero.mp4` с тем же именем.

## 4. Подстраницы сортов

6 самостоятельных статических HTML-файлов, без общего шаблона/сборки — так же,
как сейчас устроены demo1/demo2 (в проекте нигде нет переиспользуемых компонентов
между страницами, конвенция — копия разметки). Каждая страница:

1. Шапка — картинка сорта на всю ширину + название.
2. Описание сорта (текст — от пользователя, пришлёт по каждой странице).
3. Инструкция по завариванию (текст — от пользователя).
4. Мини-каталог товаров этого сорта — список карточек, данные из `catalog.json`
   (см. раздел 5), отфильтрованные по полю `category`.

Слаги: `shu-puer`, `sheng-puer`, `white`, `red`, `mandarin-shu`, `chenpi`.

## 5. Каталог МойСклад → статический JSON (демо-уровень)

Сайт статичный (GitHub Pages), прямой запрос из браузера к API МойСклада
означал бы, что логин/пароль виден всем посетителям — неприемлемо. Так как это
демо (боевая версия будет на Тильде), выбран самый простой вариант без бэкенда:

- Скрипт-расширение `moysklad-import/export_catalog.py` (использует ту же
  сессию/авторизацию, что `import_products.py`) выгружает товары из МойСклада
  и раскладывает их по 6 сайтовым категориям, формируя `catalog.json` в корне сайта.
- Каждая подстраница в `componentDidMount` делает `fetch('../catalog.json')`
  и рендерит `sc-for` по отфильтрованному списку — без запросов к МойСклад API
  напрямую из браузера, без секретов на клиенте.
- Обновление каталога — вручную, повторным запуском скрипта перед деплоем.
  Никакой автоматизации (GitHub Actions и т.п.) не делаем, т.к. это демо-контур.

**Расхождение категорий (важно):** группы, уже создаваемые `import_products.py`
в самом МойСкладе (Белый чай / Шу пуэр / Шэн пуэр / Красный чай — 4 шт. после
исправления, см. ниже), не совпадают 1:1 с 6 категориями сайта. У сайта есть
отдельные «Шу в мандаринах» (Сяо Цин Гань, позиции №26–27) и «Мандариновая
кожура» (Чэньпи, позиции №3 и №10) — на складе они относятся к группам «Шу пуэр»
(№26, №27) и «Белый чай» (№3, №10). `export_catalog.py` не привязывается к
группам МойСклада напрямую — переклассифицирует локально по номеру позиции,
описанному в разделе реализации.

**Позиция №10 уточнена:** «Юньшан Люцзинь» — это белый чай с выдержанной
мандариновой коркой (подтверждено пользователем 2026-07-31), не Лю Бао, как
предполагалось раньше без проверки. Складская категория (МойСклад) исправлена
на «Белый чай» в `moysklad-import/items.json`. Категория сайта — «Мандариновая
кожура» (вместе с позицией №3, та же комбинация чай+корка).

## Ошибки / деградация

- Если `catalog.json` не загрузился (сеть, 404) — секция каталога на подстранице
  показывает заглушку «Каталог временно недоступен» вместо пустого блока.
- Видео: `poster` служит как визуальный fallback, если видео не воспроизвелось.

## Тестирование

- Ручная проверка в браузере (Live Server / `python3 -m http.server`) — по
  правилам проекта сборки нет, автотестов для статических демо-сайтов в проекте
  не заведено, тестируем визуально: главная (hero-видео, порядок блоков),
  переходы на все 6 подстраниц, отображение каталога по каждой категории,
  мобильная адаптивность (уже частично сделана для demo2 ранее).

## Незакрытые элементы (не блокируют старт реализации)

- Видео-плейсхолдер для hero — подобрать при реализации.
- Тексты (описание сорта, инструкция по завариванию) для 6 подстраниц — от пользователя,
  до получения — на странице временный плейсхолдер-текст.
- Ссылки на каналы для блока подписки — от пользователя, до получения — используется
